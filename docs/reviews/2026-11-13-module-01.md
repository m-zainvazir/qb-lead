# Security review: module 1 (tenants, logins and isolation)

- Date: 2026-11-13
- Method: independent code review (fresh reviewer, read-only), followed by fixes and regression tests.
- Result: no critical or high findings. No cross-tenant read or write was found through REST or the API.

| # | Finding | Severity | Status | Fixed in / tested by |
| --- | --- | --- | --- | --- |
| 1 | Open redirect through control characters in `next` (`/%09/evil.com`) on `/auth/confirm` and sign-in | Medium | Fixed | `apps/web/src/lib/redirects.ts` resolves the URL as a browser would and keeps only same-origin paths |
| 2 | A tenant admin could un-revoke an invitation via REST (`revoked_at = null`), turning an owner's revoked admin invitation into an admin seat | Medium | Fixed | `20261113181345_hardening.sql`: no UPDATE grant on invitations; `private.revoke_invitation()`; admins manage member invitations only. Tests: `test_admin_cannot_unrevoke_an_invitation`, `test_admin_cannot_revoke_owners_admin_invitation` |
| 3 | Changes made directly through Supabase REST (roles, removals, invitations, renames) left no audit entry; REST invitations skipped the daily cap | Medium | Fixed | Audit entries now come from triggers on `memberships`, `invitations`, `tenants`; caps and "already a member" live in a BEFORE INSERT trigger. Tests: `test_direct_role_change_is_audited`, `test_rest_role_change_is_audited`, `test_daily_invitation_cap`, `test_inviting_an_existing_member_is_refused`, `test_cross_tenant_invite_reveals_nothing` |
| 4 | After sign-out everywhere or a password reset, a stolen access token kept working on the REST API until it expired (up to 15 min) | Medium/low | Fixed | PostgREST pre-request hook `private.check_request()`. Test: `test_rest_refuses_a_revoked_session` |
| 5 | Two owners demoting each other at the same moment could leave a company with no owner | Low | Fixed | `keep_one_owner()` locks the company row first |
| 6 | A new platform admin is protected only by a password until they enrol MFA, so whoever holds the password could enrol first | Low | Fixed | `supabase/snippets/create_platform_admin.sql` only inserts users who already have a verified TOTP factor |
| 7 | Company cap and invitation cap could be raced with parallel requests | Low | Fixed | Advisory locks in `create_tenant()` and the invitation trigger |
| 8 | The tenant-table template granted UPDATE on every column (including `tenant_id`) and let any member delete | Low | Fixed | Template grants column-level UPDATE and needs owner/admin to delete. Test: `test_users_cannot_move_rows_between_tenants` (every tenant table) |
| 9 | Audit IP is always the Next.js server's address | Low | Open | Needs the web server to forward the client IP and the API to trust it only from that host. Planned with the deploy work (module 10). |
| 10 | Tenant name went unescaped into invitation emails; CR/LF caused a 500 after commit | Low | Fixed | DB constraint `tenants_name_printable`, API pattern, mailer catches `ValueError` |

Also noted: leaked-password protection (HIBP) is a hosted-Supabase setting; it is listed in `docs/runbook.md` for staging.

A bug in the first hardening migration (`text[] || 'literal'` in `audit_tenants()`) was caught by the new tests and fixed in `20261113181830_fix_audit_tenants.sql`.
